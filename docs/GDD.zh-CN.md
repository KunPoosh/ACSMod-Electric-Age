# 电气时代 — GDD v0.1 讨论草案

日期：2026-09-27。状态：待讨论；本文件不是已批准的实现规格。

## 1. 已确定方向

- 独立 Acbric Java MOD：电气时代 / Electric Age。
- 建立有实际数量与收支约束的电力：发电机提供输出，蓄电池提供储能，用电设备具有额定功率。
- 探索哪些通用能力适合成为 Acbric 公共接口；电力玩法与框架职责分开。
- 当前仓库只有构建及初始化入口，没有电力功能、原版设备改造或存档规则。

## 2. 玩家体验提案

核心体验：通过设计发电、储能与负载组合，在持续作战能力、短时爆发、空间、重量、造价及受损韧性之间作选择。

循环提案：设计供需 → 战斗观察收支 → 应对发电机或电池受损 → 战后调整设计。

具体时代设定、美术风格、科技树和最终设备清单待讨论；不自动采用 ProjEOL 的设定或素材。

## 3. 首个可玩版本提案

- 整船共享电力，不要求布线；船体断裂后分别结算。
- 最小设备组合：一种发电机、一种蓄电池、一种连续负载；脉冲武器列为后续扩展。
- 电量附着在电池模块实例；整船只汇总与分配，不凭空复制能量。
- 有明确的缺电行为及只读状态显示；存读档和复制规则尽早纳入设计。
- 发电机受到燃料、人员与存活状态影响，具体降额规则待定。
- 不自动修改所有原版设备。新增设备优先还是原版改造优先，待用户决定。

这是一组讨论建议，不是已确认的首版范围。

## 4. 待决策清单

| 议题 | 讨论起点 | 影响 |

## 5. 技术约束与验收方向

- 按模拟时间结算；暂停、倍速和回放不得由现实时间驱动充电。
- 总收支守恒。不能把负电量截断后仍让所有设备正常运行。
- 缺电不冻结着火、爆炸、水淹等原生更新。
- 修复、断裂、复制与恢复不会重复创建储能。
- 不在 UI 绘制中推进资源，不让每个负载重新扫描全船。
- 自动结算、电量延续及联机同步需要各自设计，不因战斗功能可用而默认完成。
- 不预先承诺某个游戏版本、帧率或联机模式已兼容。

建议里程碑：M0 工程骨架 → M1 确定 GDD → M2 隔离电力核心 → M3 最小可玩内容与存储 → M4 按约定扩展模式与内容。只有 M0 已着手，本表不授权自动实施后续阶段。

## 6. 研究来源

本工作区的《ARC真实电力系统源码可行性研究-20260927》及 1.2.15.2 / 1.2.15.3 / 1.2.14 静态字节码对照。研究包含 9 个工作子系统：定义、实例状态、调度、设备、损坏、存储、UI、战役/AI、联机/回放。研究中的 ARC 是当时讨论背景，本 MOD 为新的独立项目。

游戏反编译资料与实验输入留在工作区外部研究目录，不复制进本仓库。
