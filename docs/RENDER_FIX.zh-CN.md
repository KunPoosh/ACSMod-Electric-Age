# dev.3 渲染配套修复

2026-09-27。[English](RENDER_FIX.md)

用户的对照图揭示 dev.2 的缺漏：模块内部偏亮，装甲呈平面色块、缺少板缝与倒角；MOD 详情报告 `ea_devices`、`ea_propeller` 没有 damaged/fragments sheet。之前只检查了内部视图和一般 GPU 绘制，漏掉了装甲覆盖及原版 MOD 警告检查。

## 原因

dev.2 的 `SpritesheetBundle` 只有 `name`，没有 `bump` 和 `fragments`。用户交付的受损彩色图已在状态图集中使用，但它不是原版所需的凹凸图/碎片分区配置，不能代替原版衍生受损图和碎片映射。

原版 `Appearance.lockMaskedBevelledShader` 在装甲图集或模块遮罩图集没有 bump 纹理时，将光照参数设为空，退回简化着色器。因此缺少的是模块渲染配套，连带使其上方原版装甲的板缝、倒角和光照失效；不是玩家缺装框架或另一个 MOD。

原版 `SpritesheetBundle` 仅在 bump 与 fragments 均声明时提供 damaged/fragments 关联，随后由原版资源生成流程烘焙光照、受损、碎片及映射文件。

## 修复

- 为主体图集、推进器外部动画和炮管提供同尺寸 bump 与 fragments 输入，并在三个 bundle 中声明。
- 构建时生成中性表面及轮廓法线的基础凹凸图；按 8 像素区块建立碎片分区，由原版合并并生成实际碎片。透明区域使用原版白色“无碎片”标记，避免受损生成填满背景。
- 沿用已经交付的受损/运行状态彩色图，原版破坏阶段另有其衍生受损图。源 PNG 与 Aseprite 母稿不改写，不复制原版美术。
- 数值、电网算法、存档格式和指令规则不变。基础凹凸图可在后续由美术提供更细的材质法线替换，当前修复接通原版完整渲染路径。

## 更新

关闭游戏，用 `Electric-Age-0.1.0-dev.3.jar` 替换 dev.2 JAR，避免同时保留两个同 ID 版本。正常启动时 Acbric 更新配套资源，游戏重建衍生图；首次生成需要等待。已手工修改过配套资源的目录，按 Acbric 的冲突提示处理，不强行覆盖个人改动。

不需要额外下载素材包、重画整套模块或删除存档。游戏第一次检查未生成的衍生图时可能在日志中短暂提示不存在，之后应完成生成；验收依据是生成后纹理实际加载、MOD 详情无缺图警告以及装甲/受损场景正确显示。准确测试结果见 [TESTING](../TESTING.zh-CN.md)。
